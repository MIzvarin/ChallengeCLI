# FitAgent

Локальный терминальный помощник для взрослых (18+): профиль, цели, динамика веса
и чат о питании и тренировках. Python 3.9+, Textual, SQLite.

## Запуск

```sh
python3 -m venv .venv
.venv/bin/python3 -m pip install --upgrade pip
.venv/bin/python3 -m pip install -e .
source .venv/bin/activate
fitagent
```

В созданном `.env` заполните `OPENCODE_API_KEY`. Не передавайте ключ в чат и не
коммитьте файл: `.env` и его варианты исключены из Git. Шаблон — `.env.example`.
Приложение читает `.env` текущей директории, затем `~/.config/fitagent/.env`;
переменные окружения имеют приоритет. После изменения ключа перезапустите FitAgent.

По умолчанию запросы идут **напрямую**, без процесса OpenCode, в
`https://opencode.ai/inference/go/openai/v1/chat/completions`, модель
`deepseek-v4.1-flash`. Переопределения: `FITAGENT_API_URL` (только HTTPS),
`FITAGENT_MODEL`, `FITAGENT_DATA_DIR`. Ответы и сводки используют одну модель.
Планирование целей, извлечение фактов и отдельную проверку безопасности выполняет
**`gpt-6-luna` через Responses API того же Go**:
`https://opencode.ai/inference/go/openai/v1/responses`, с тем же `OPENCODE_API_KEY`.
Переопределения модели/URL чата не меняют маршрут памяти; отдельный ключ не нужен.
Отправляются собственный User-Agent `fitagent/0.1.0` и стабильный `x-opencode-session`.

**Ограничение Go:** сервис ориентирован на coding-agent трафик. Применимость
подписки к фитнес-чату не подтверждена; интеграция оставлена по согласованию
с пользователем. Доступ, тарифы и лимиты определяет провайдер. Реальные платные
запросы при разработке не выполнялись. В настройках приватности Go для DeepSeek
может потребоваться разрешить регион Global.

## Интерфейс

Вопросы и ответы показаны отдельными блоками с рамкой, подписью автора и отступами;
так же оформляется восстановленная история. Ответы сохраняют форматирование Markdown.

Чат отвечает только о питании, тренировках, прогрессе и использовании FitAgent.
Для посторонних вопросов системный промпт предписывает краткий отказ с пояснением
тематики. В смешанных запросах агенту предписано отвечать только на часть по теме;
соблюдение этих правил зависит от модели, отдельного фильтра в приложении нет.

- `/profile` или Ctrl+P — профиль **только для чтения**. Изменения сообщайте в чате.
- `/progress` — последние 30 измерений веса, упорядоченных по дате измерения.
- `/logs` или Ctrl+L — показать/скрыть нижнюю панель логов и расхода токенов,
  не перекрывая чат. Панель обновляется каждые две секунды и после ответа.
  Счётчики закреплены сверху в контрастном блоке с выделенными числами;
  лента событий отделена подписанным разделителем и прокручивается независимо.
  В ленте подключение checkpoint, смена темы, факты в контексте, сжатие истории,
  предупреждения/блокировки безопасности и ошибки проверки безопасности/памяти.
  Успешные проверки скрыты; тексты диалога и личные данные не показываются.
- `/tokens` — отдельное окно с графиком накопленного расхода всех обращений к API
  и тем же верхним блоком счётчиков, что в `/logs`. Escape или кнопка возвращают в чат.
  X — порядковый номер обращения, Y — известная сумма входных и выходных токенов.
  Длинная история сжимается по ширине окна с сохранением конечной суммы;
  `?` отмечает обращения или группы с неполной статистикой. Без статистики график
  не подменяет неизвестный расход нулём. Открытие окна не обращается к модели.
- `/clear` — **без подтверждения** удаляет профиль, все цели, переписку, изменения,
  закреплённые факты, сводки и логи; очищает экран, создаёт новую сессию и открывает профиль.
  `.env`, API-ключ и настройки подключения остаются без изменений.
- `/help` — краткая справка.
- `/memory` — факты, номера, общая/тематическая область применения, тема-источник и сроки.
- `/memory edit НОМЕР новый текст` — исправить факт (1–500 символов), без API.
- `/memory delete НОМЕР` — удалить факт, его версии и цитаты-источники из памяти, без API.
   Исходная переписка остаётся: удаление факта не удаляет его упоминаний из недельной истории.
- Для ограничений безопасности, лекарств, добавок и измерений локальная правка/удаление
  отклоняются: сообщите исправление или прекращение в чате для проверки Luna.
- `/memory history НОМЕР` — журнал предыдущих/новых значений и дат факта.
- `/memory archive` — архив среднесрочной памяти завершённых целей.
- `/confirm НОМЕР` — подтвердить предложенное изменение или завершение задачи/цели;
  `/cancel НОМЕР` — отменить предложение. После изменения данных старое согласие не принимается.
- `подтверждаю план` — принять проверенный план и его предупреждение, перейти к выполнению.
  При опасности подтверждение не принимается: нужны корректировки и новая проверка.
- `/exit` или Ctrl+Q — закрыть приложение без удаления сохранённых данных.
- `fitagent logs` — те же последние 200 значимых событий без открытия TUI.

Темы переключаются автоматически: общая лента остаётся хронологической, а переходы отмечаются
«Новая тема», «Возвращаемся к теме», «Короткое отступление» или «Связанные темы».
Ручных команд переключения (`/topics`, `/resume`, `/checkpoint`) нет.

Во время ответа показывается монохромный анимированный индикатор с временем
ожидания. После ответа или ошибки он скрывается; фиктивного процента прогресса нет.

`/clear` выполняется, когда приложение не ожидает ответа модели. Все записи очищаются
одной транзакцией SQLite, включая факты, их версии, источники и вопросы уточнения;
файл БД остаётся пригодным для новой сессии. Это логическое
удаление, не гарантированное физическое стирание с носителя или из резервных копий.
Данные, уже переданные провайдеру модели, эта команда удалить не может.

При первом запуске FitAgent задаёт вопросы **в чате, по одному**, без стартового окна:
дата рождения `ГГГГ-ММ-ДД`, рост, вес, пол, цель, необязательный целевой вес;
затем аллергии/непереносимости, пищевые предпочтения, привычный режим питания,
принимаемые добавки, лекарства и имеющаяся программа тренировок.
Все ответы обязательны. Вместо «да» сразу опишите подробности; отсутствие обозначьте «нет».
Для препаратов сообщите названия и известные дозировки/частоту: неизвестное не додумывается.
Возраст вычисляется из обязательной даты рождения на текущую дату. Дробные числа — с точкой.
Незавершённый опрос восстанавливается после перезапуска; после сохранения он не повторяется.
До завершения опроса можно исправить любой ответ: `аллергии: ...`, `лекарства: ...`,
`дата рождения: ...`, `цель: ...` и аналогично другим полям. После ошибки проверки — `сохранить`.
Для итогового сохранения данных нужна проверка Luna. Цель записывается как желаемая,
а не как разрешённый к выполнению план: дальше начинается конвейер цели.

ИМТ целевого веса вне 18,5–24,9 вызывает предупреждение, но не блокировку опасности.
ИМТ не является диагнозом и не учитывает мышечную массу. Перед выполнением проверяются
формулировка, сроки, конкретный способ достижения и текущие данные пользователя.

Через 7 суток приложение напоминает сообщить изменения в чате; повторного полного опроса
или редактируемой формы нет. Следующее напоминание — через сутки, если профиль не обновлён.
Напоминания работают только в запущенном приложении; фоновых уведомлений нет.

### Строгий конвейер цели

`1. Планирование → 2. Валидация → 3. Выполнение → 4. Готово`.
Единственный обратный переход — **3 → 2**; произвольного переключения этапов нет.
На этапе 2 уточнения и исправления остаются внутри валидации, без возврата на этап 1.
Новая цель запускает отдельный конвейер. Этап виден рядом с профилем и сохраняется в SQLite.

1. **Планирование.** Собираются недостающие общие сведения об аллергиях, предпочтениях,
   питании, тренировках, лекарствах и добавках. Давность уточняется по существующим срокам
   категорий памяти; вес — через 7 суток. Известные аллергии/противопоказания не истекают.
   Luna задаёт вопрос либо предлагает полный черновик и проверяемый критерий завершения.
2. **Валидация.** Отдельный структурированный вызов Luna проверяет именно черновик плана.
   - Всё хорошо — план можно принять фразой **«подтверждаю план»**.
   - Предупреждение — показываются причина и пометка «рекомендация»; эта же фраза явно
     принимает предупреждение вместе с планом. До неё выполнение не начинается.
   - Опасность — конкретная прямая угроза жизни или тяжёлого вреда, например опасное
     взаимодействие, анафилаксия или экстремальный способ похудения. Умеренное отклонение
     ИМТ, неизвестная дозировка или отсутствие идеальных показателей сами по себе не block.
     Показываются причина и безопасные корректировки; напишите **«предложи корректировки»**
     либо опишите свой вариант. Подтверждение опасность не снимает.
3. **Выполнение.** При **каждом открытии приложения** задаётся вопрос о прогрессе и
   самочувствии, без обращения к API. Проблемы, изменения плана или значимых данных
   возвращают на валидацию; исправленный план нужно принять заново. Обычное сообщение
   о прогрессе или повторное подтверждение актуальности не меняет этап автоматически.
4. **Готово.** Достижение сначала предлагается в чате; только `/confirm НОМЕР`
   завершает цель и архивирует её память. Критерий согласуется при принятии плана.
   Новое измерение, подтверждающее результат, сохраняется вместе с предложением завершения,
   без генерации нового плана. Ожидание подтверждения сохраняется после перезапуска.
   `/cancel НОМЕР` отменяет завершение; если данные изменились, перед продолжением нужна валидация.
   Для старого предложения без привязки к плану приложение попросит сообщить о достижении
   ещё раз; автоматического принятия или удаления сохранённых данных не происходит.

«Да» или «хорошо» не заменяют явного принятия плана. Оно привязано к проверенным данным;
после изменений старое согласие не применяется. Ошибки API/схемы не считаются опасностью
и не продвигают конвейер; ответ, факты и этап фиксируются одной транзакцией.
Самочувствие и восстановление также входят в проверку актуальности, включая `/memory edit`.
Согласие относится к предложению, показанному **в текущем окне**. Если другое окно изменило
план, критерий или предупреждение, приложение сначала покажет новое предложение; нужно
прочитать его и подтвердить заново. Независимые задачи/обсуждения можно завершать и без цели.
Уже существующие цели без состояния конвейера начинают с планирования, не угадывая,
был ли старый план когда-либо принят. Просмотр профиля, памяти и локальные команды доступны.
Планирование/оценка необходимости коррекции — дополнительный запрос Luna на сообщение;
открытие приложения и точная фраза принятия плана запросов к API не выполняют.
Строгая схема не гарантирует медицинскую точность или правильность оценки тяжести риска.

## Данные, контекст и кеш

База: `~/.local/share/fitagent/fitagent.sqlite3`, либо `FITAGENT_DATA_DIR`.
Рассчитана на одного пользователя. Каждый профиль — новый снимок. Вес хранится отдельными
датированными фактами `measurements`; профиль подставляет последнее измерение по его дате,
не по времени сообщения. Подтверждение изменения цели не создаёт фиктивного измерения веса.
Исправление старого измерения по номеру сохраняет его исходную дату, если пользователь
явно не исправил и дату; такая правка не подменяет более свежий вес в профиле.
Изменение цели создаёт новую запись `goals`; заменённые и завершённые записи остаются в истории.
`messages` хранит отдельные вопросы/ответы с датой, временем и статусом,
`changes` — подтверждённые изменения по дням; `summaries` — кеш сводок,
`events` — технический аудит. При запуске экран восстанавливает всю сохранённую
переписку, включая сообщения старше недели; история доступна прокруткой без лимита
строк. Неудачные и незавершённые вопросы помечаются и автоматически не повторяются.
Отображение всей истории требует памяти пропорционально её объёму.
Ничего не удаляется при суммаризации.

### Слои памяти и жизненный цикл

- **Долгосрочная:** дата рождения, пол, рост, устойчивые сведения об опыте/оборудовании.
- **Среднесрочная:** цель, история веса и других измерений, привычный режим и принятый план
  питания, текущие тренировки, добавки и лекарства. Дневника съеденного пока нет.
- **Краткосрочная:** текущее обсуждение, checkpoint, незавершённые вопросы, самочувствие.
- **Отдельно:** ограничения безопасности (аллергии, противопоказания) и предпочтения
  (продукты, формат общения). Давность не отменяет известное ограничение безопасности.

Sticky facts обновляются из явных утверждений пользователя без обязательного слова «запомни».
Вопрос о добавке не означает её приём, предложение ассистента не становится принятым планом.
После успешной записи приложение само добавляет сообщение **«Память обновлена»**.
Изменения профиля/цели и исправления существующих ограничений требуют отдельного подтверждения.
Факты и инварианты имеют журнал значений, даты записи/действия и источник;
история профиля и целей хранится снимками и записями `changes`.

Завершение задачи или достижение цели сначала предлагается в чате. Только после `/confirm`
задача закрывается, её checkpoint удаляется и краткосрочное состояние исключается из контекста.
При достижении цели среднесрочные сведения архивируются в `memory_archives`.
Измерения, текущие общие режимы питания/тренировок, лекарства, добавки и инварианты сохраняются;
связанные с завершённой целью планы уходят из активного контекста. Новую цель задайте в чате.
Исходная переписка остаётся видимой в ленте; закрытые задачи не восстанавливаются автоматически.

### Отдельная проверка безопасности

Помимо извлечения памяти, Luna вызывается отдельно до генерации ответа и после неё,
до показа пользователю. Изменения профиля/ограничений также проверяются, включая подтверждение.
Проверка получает актуальную/предлагаемую цель и тот же контекст обсуждения (историю и checkpoints),
что основная модель, чтобы понимать ссылки вроде «можно его добавить?».
Непроверенный черновик плана не показывается. При принятии плана локально проверяются
этап, результат Luna, актуальность и отпечаток данных: изменившееся предупреждение/план
нельзя принять старым согласием. Исправления ограничений повторно проверяются через API
при подтверждении. Статус block нельзя снять подтверждением; warning не создаёт цикла согласий.
Контекст собирается до проверки запроса: при переключении тем это может потребовать
создания checkpoint даже для запроса, который затем будет заблокирован.
Лекарства и добавки учитываются вместе с аллергиями, противопоказаниями и текущими данными.
Luna назначает строгость и возвращает закрытый JSON: `status`, `description`, `checks`.
Каждый элемент `checks` содержит `rule_id`, `strictness`, `status` и краткое основание.

- `allow` — проверка пройдена;
- `warning` — предупреждение, например неизвестна дозировка; запрос не блокируется;
- `block` — известное нарушение безопасности; блокируется **только этот запрос**.

Для валидации цели warning останавливает переход к выполнению до принятия плана.
block предназначен для конкретной угрозы жизни/тяжёлого вреда, не для небольшого отклонения ИМТ.
Проверка плана просит безопасную корректировку, а не только формальный отказ.

При отказе FitAgent пишет, что не может выполнить, затем отдельной строкой — конкретную
причину риска и возможный следующий шаг (безопасный вариант или другой вопрос).
Сбой проверки описывается отдельно: это ошибка сервиса/обработки, а не вывод об опасности
вопроса. Непроверенный ответ при этом не показывается, данные не изменяются.

Недостаток подробностей не ослабляет известную аллергию или несовместимость. Основная модель
получает только итоговый статус и краткое описание, без массива проверок/скрытых рассуждений.
Python проверяет типы, обязательные поля, покрытие правил и согласованность статусов.
Фиксированного лимита 64 элементов `checks` нет: проверяются все обязательные правила,
в том числе для пакета из 32 новых ограничений. Лимит вывода Luna остаётся 8192 токена.
Для каждого обращения строгая схема задаёт ровно столько проверок, сколько требуется,
и разрешает только их номера. Прочие риски учитываются в `system`, а не раздувают массив.
Пояснение одной проверки ограничено 80 символами; общая причина отказа — 700.
Это предотвращает неограниченное разрастание ответа без пропуска ограничений, повышения
лимита токенов и автоматических платных повторов. Неполный результат по-прежнему отклоняется.
Ошибка API, отказ модели или некорректная структура также блокируют запрос: небезопасный
черновик не показывается и не сохраняется. Автоматического ослабления правил и повторов нет.
Другие вопросы, просмотр профиля и управление памятью остаются доступны.
Исправить неверные сведения может пользователь через чат с предупреждением и подтверждением.
Отдельный LLM-вызов и строгая схема **не гарантируют медицинскую/смысловую точность**.

Локальная проверка сохранённого JSON без API:

```sh
.venv/bin/python3 scripts/check_safety.py response.json --rule fact:1
```

Коды выхода: `0` — корректный allow/warning, `2` — корректный block, `1` — ошибка протокола/файла.
`-` вместо пути читает JSON из стандартного ввода. Файл не включайте в Git: он может быть чувствительным.

### Sticky facts — закреплённые факты

Память дополняет недельную историю активной темы и суммаризацию. Перед ответом Luna
получает текущий вопрос, факты, каталог тем, checkpoint активной темы и максимум предыдущий обмен
для понимания короткого согласия (до 12 000 UTF-8 байт, иначе этот обмен не отправляется).
**Архив автоматически не разбирается**: источником новых фактов может быть только новый вопрос.
При запуске и открытии `/memory` запросов к API нет. Извлечение и выбор темы — одно общее
обращение Luna на новый вопрос, с расходом токенов и дополнительным временем ожидания.

Категории: пищевые ограничения и вкусы, режим питания, бюджет/готовка, тренировочный опыт
и текущий режим, оборудование, расписание, сообщённые ограничения здоровья, самочувствие,
восстановление, привычки, выбранные пользователем планы, предпочтения общения.
Лекарства, добавки, принятый план питания и измерения имеют отдельные категории.
Профиль и официальная цель меняются через предложения в чате с подтверждением, `/profile` — read-only.

Значение имеет строгую структуру: `text` — краткое утверждение, `quantity` и `unit` — явно
сообщённое число и единица (либо `null`), `qualifier` — оговорки и условия (либо `null`).
Источник — дословная цитата нового сообщения и его номер; даты и период хранятся отдельно.
Ручная правка обычных фактов помечается как ручной источник; числовые поля при ней очищаются.
Для измерений локальная текстовая правка запрещена, чтобы не терять числовое значение.

У факта независимы:
- `applicability=global`, `topic_id=null` — общее сведение (например аллергия или оборудование);
- `applicability=topic`, `topic_id=номер` — условие конкретного меню, плана или обсуждения;
- `source_topic_id` — где прозвучало подтверждение, не ограничение области действия;
- `scope` — обычный режим или временное исключение, не тема.

Аллергию можно сообщить в теме завтраков, но она останется общей для всех ответов.
«Для этого меню бюджет 5000» относится только к теме этого меню. В ответ включаются общие
и тематические факты активной ветки; для смешанного вопроса — явно выбранных связанных веток.
Пищевые и медицинские ограничения не разрешается ограничивать одной темой.
Прежние факты/уточнения мигрируют в global, без потери версий и цитат и без угадывания источника.

Luna получает `text.format: {type: "json_schema", strict: true, ...}`; Python дополнительно
проверяет схему, конечные числа, категории, источник-цитату, идентичность и сроки.
Повторы объединяются по `category/key/scope/applicability/topic_id`; значения заменяются с сохранением
версий. Временные исключения имеют отдельный scope. Семантическое сопоставление делает
модель: строгая схема не гарантирует верного понимания; проверяйте память через `/memory`.
Неоднозначное противоречие сохраняет старое значение и вопрос уточнения для следующего ответа.

Перепроверка при необходимости: самочувствие/восстановление — через 1 день; режим питания,
тренировок и привычки — 14 дней; расписание, бюджет и планы — 30 дней (план со сроком — в конце).
Явный конец периода исключает временный факт из текущего контекста, но не удаляет запись.
Пищевые и медицинские ограничения не истекают автоматически: давность не означает выздоровление.
Если при обновлении срок не упомянут, прежнее окончание сохраняется; явное «бессрочно» снимает его.
Итоговый период проверяется до ответа: окончание не может предшествовать началу.
При будущей постоянной смене режима прежняя версия действует до даты перехода, новая — начиная
с этой даты. Это сохраняется после перезапуска. Правка запланированной версии не включает её раньше
срока; изменение даты переносит переход. Отзыв или удаление факта прекращает и прежние версии.
Luna явно различает правку последнего этапа (`update_mode=replace`) и добавление следующего
(`append`). После сохранённого «с 21 ноября четыре тренировки» новый запрос «затем с 28-го пять» сохраняет оба этапа;
«перенесём начало с 21-го на 28-е» меняет дату последнего этапа. Следующий этап должен начинаться
в будущем, позже последнего запланированного. При неясном намерении требуется уточнение.
Перенос последнего этапа на дату не позже начала предыдущего отклоняется с пояснением:
этапы не отменяются и не переставляются автоматически.
Если прежний факт ещё действует, а будущая версия имеет другую область применения,
текущее значение можно обновить отдельно. Прежняя версия завершается в момент обновления,
а будущий этап сохраняется. Например, новый общий лимит расходов на продукты не отменяет
запланированный лимит конкретного меню. Проверяются интервалы всех действующих и будущих версий:
одна идентичность не может одновременно передавать в контекст два значения.
Обновления одного факта в одном ответе Luna отклоняются как конфликтующие и при сочетании
явного номера с неявным совпадением по идентичности; частичные изменения не сохраняются.
На один факт допускается одна операция в ответе Luna; несколько этапов добавляются отдельными сообщениями.

Бюджет памяти — 20 000 UTF-8 байт, отдельно от истории; в извлечение входят последние 30 измерений,
в ответ — последнее действующее измерение каждого показателя, полный ряд остаётся в БД.
При переполнении остальных фактов запрос останавливается
с предложением сократить память, без молчаливого удаления ограничений. Незавершённый ответ,
отказ Luna, ошибка API или неверная схема не принимаются как факты. Извлечение не повторяется
автоматически и не заменяется обычным JSON/текстом. При ошибке вопрос остаётся в поле ввода.
Факты, источники, отметка обработки вопроса и ответ записываются одной транзакцией только
после успешного ответа; неудачный вопрос не изменяет память и не повторяется при запуске.
Снимок памяти и его ревизия читаются одной транзакцией: параллельное удаление или исправление
не может быть отменено записью устаревшего снимка.

### Автоматические темы и checkpoints

В том же строгом ответе Luna выбирает `continue`, `switch`, `resume`, `detour` или `mixed`.
Короткое уточнение не должно считаться новой темой; при неоднозначности инструкция требует
оставить текущую тему и при необходимости задать уточняющий вопрос. Выбор смысловой, не по таймеру.
Отступление имеет собственную ветку и ссылку на родительскую; возврат тоже определяется по смыслу.

Перед уходом с темы Flash создаёт checkpoint: датированную сводку с границами исходных сообщений.
Промпт требует различать явно принятые решения, советы ассистента, открытые вопросы и следующий шаг.
При новом сохранении используется предыдущий checkpoint и ещё не покрытые завершённые сообщения
той же темы; оригиналы не удаляются. При возвращении checkpoint работает и после недельного срока.
Обычная недельная история ответа содержит только непокрытые сообщения активной темы.
В смешанном вопросе подключаются сводки выбранных связанных тем, без слияния полных историй.

Checkpoint не становится новым фактом и не откатывает профиль. Если профиль/цель изменились,
модель получает отметку `profile_changed`, актуальный профиль и применимые sticky facts.
Темы определяются до суммаризации истории, чтобы не сжимать вместе независимые обсуждения.

Ветки, обе реплики, факты, источники, переход и checkpoints фиксируются одной транзакцией.
При ошибке классификации, сводки, ответа или записи переключение не фиксируется.
Названия тем, сообщения и тексты checkpoints не пишутся в технический аудит.
После обновления старая завершённая переписка локально группируется как «Общий диалог»:
это не семантический разбор архива, при открытии API не вызывается.

Checkpoint ограничен 20 000 UTF-8 байт. Его создание — дополнительные запросы Flash
(для большой темы несколько порций); они учитываются в токенах, не повторяются автоматически.
Строгая схема проверяет формат маршрута и ссылок, но не гарантирует правильное распознавание
темы или смысловую точность сводки. Каталог тем растёт с диалогом; отдельного лимита всего запроса нет.

### Недельный контекст и суммаризация

Ответы, оценка цели и сводки содержат базовый системный промпт (консервативная оценка
меньше 3000 токенов) и полный актуальный профиль с целью. Ответы используют
историю активной темы за 7 суток после границы checkpoint; ошибочные/незавершённые вопросы исключены.
При превышении бюджета истории 50 000 UTF-8 байт старая часть суммаризируется порциями,
последние полные записи в пределах бюджета 12 000 остаются дословными.
Сводка ограничена бюджетом 20 000. Для обычного ответа и проверки цели приложение
не передаёт max_tokens; лимиты генерации по умолчанию определяет API провайдера.
Ограничений длины вопроса и общего размера запроса в приложении нет;
предельный контекст определяет API провайдера.

**Учёт консервативный:** один UTF-8 байт считается верхней оценкой одного токена,
с отдельным резервом на формат сообщений. Это не точный токенизатор DeepSeek:
для русского текста суммаризация может начинаться заметно раньше 50 000
фактических токенов. Фактическая статистика API пишется в аудит, если доступна.
Результат сводки также проверяется по байтовому бюджету, без обрезания оригиналов.

Ключ кеша включает назначение (сводка/checkpoint), модель, полный системный контекст и исходные данные.
Внутренний аудит сохраняет начала/концы операций, проверки профиля, кеш и ошибки API,
но `/logs` и `fitagent logs` показывают только значимые события по-русски:
- «Checkpoint подключён»: номер темы и границы сообщений подключённой сводки;
- «Тема изменена»: номера прежней и новой темы, вид перехода (без continue и первой темы);
- «Факты прочитаны в контекст»: номера и количество применимых фактов, без их значений;
- «История сжата»: размер истории до/после в UTF-8 байтах, включая применение кешированной сводки.
- «Проверка безопасности»: этап (профиль, запрос, изменение данных, ответ, оценка цели,
  валидация плана, изменение желаемой цели)
  и результат «предупреждение» или «заблокировано»; успешный результат `allow` скрыт;
- «Ошибка проверки безопасности»: этап и подсказка повторить попытку;
- Для новых сбоев проверки безопасности также указывается причина из безопасного словаря:
  например, пропущены правила, повтор номера проверки или несогласованный итоговый статус.
- «Ошибка проверки памяти»: факты не изменены, запрос нужно повторить.

Для проверок не выводятся тексты вопросов/ответов, причины от модели, личные данные,
внутренние имена этапов и необработанные исключения. Уже сохранённые события проверок
также видны после перезапуска, без повторных обращений к API.
Технический аудит новых сбоев содержит код причины, фазу получения/валидации, путь поля
схемы и необходимые счётчики/статусы — без исходного результата модели и номеров правил.
Отдельно различаются HTTP/сетевой сбой, тайм-аут, незавершённый/обрезанный ответ,
пустой результат, отказ модели и неверный протокол сервиса.
Для старых ошибок без этих метаданных точная причина задним числом не восстанавливается.

Чтение означает включение данных в подготовленный контекст ответа, а не доказанное
использование моделью. Проверки бюджетов и просмотр /memory не создают события чтения.
Подготовка контекста может завершиться последующей ошибкой API: событие чтения не означает успех ответа.
Создание checkpoint не считается его использованием: событие появляется при подключении
сводки к ответу (основная или связанная тема). Неизменившаяся тема не засоряет ленту.
Лимит 200 применяется к значимым событиям; технические записи их не вытесняют.
Старые записи не удаляются. Для событий, ранее не записывавшихся, история не выдумывается.
Ошибки проверок дополнительно видны в ленте; прочие технические ошибки в неё не попадают.
Учёт токенов и график не меняются.

`api_usage.cached_tokens` —
отдельный кеш провайдера; `null` означает, что API не сообщил статистику.
Логи объясняют решения приложения, а не раскрывают скрытые рассуждения модели.
Панель `/logs` показывает входные токены **всего контекста** текущего/последнего
запроса чата и выходные токены ответа по `usage` API, а не по локальной оценке.
До получения статистики отображается «нет данных». Общий расход — сумма входных
и выходных токенов **всех** обращений: ответы, оценка цели, суммаризация, checkpoints и Luna, включая
обрезанные и некорректные ответы, если API сообщил `usage`. Кешированные токены
уже входят во входные и повторно не прибавляются; это счётчик токенов, не стоимости.
Сумма берётся из всего сохранённого аудита, не только последних 200 событий;
восстанавливается после перезапуска, обнуляется `/clear`. Если статистика отсутствует,
показываются известная сумма и число обращений без полной статистики, без догадок
о расходе. Для старых ошибок, когда `usage` не сохранялся, восстановить расход нельзя.
Автоматических повторов платных запросов нет; при ошибке текст остаётся в поле ввода.

**Приватность:** SQLite не зашифрована (каталог создаётся с правами 700, файл — 600).
Профиль, цели, история активной темы, checkpoints, каталог тем и факты передаются внешнему API Go.
Для OpenAI (Luna) условия Go допускают хранение запросов до 30 дней, даже при `store=false`:
этот флаг отключает сохранение объекта Responses, но не журналы безопасности провайдера.
Ключи, тексты сообщений, цитаты и значения фактов/профиля не пишутся в технический аудит. Медицинские
рекомендации требуют проверки специалистом; приложение не заменяет врача.

## Проверки

```sh
.venv/bin/python3 -m pip install -r requirements-dev.txt
.venv/bin/python3 scripts/lint.py
.venv/bin/python3 -m unittest discover -s tests -v
```

Тесты используют подменный API: валидация, напоминания, история целей,
недельный контекст, суммаризация, кеш, строгий Responses API, факты/сроки/темы/дубли, checkpoints,
откаты транзакций, ошибки и headless-сценарии Textual. Реальные платные запросы не выполнялись.
Документация каждого класса расположена рядом с исходным Python-файлом.
