# FitAgent

Локальный терминальный помощник для взрослых (18+): профиль, цели, динамика веса
и чат о питании и тренировках. Python 3.9+, Textual, SQLite.

## Запуск

```sh
python3 -m venv .venv
.venv/bin/python3 -m pip install --upgrade pip
.venv/bin/python3 -m pip install -e .
source .venv/bin/activate
fitagent
```

В созданном `.env` заполните `OPENCODE_API_KEY`. Не передавайте ключ в чат и не
коммитьте файл: `.env` и его варианты исключены из Git. Шаблон — `.env.example`.
Приложение читает `.env` текущей директории, затем `~/.config/fitagent/.env`;
переменные окружения имеют приоритет. После изменения ключа перезапустите FitAgent.

По умолчанию запросы идут **напрямую**, без процесса OpenCode, в
`https://opencode.ai/inference/go/openai/v1/chat/completions`, модель
`deepseek-v4.1-flash`. Переопределения: `FITAGENT_API_URL` (только HTTPS),
`FITAGENT_MODEL`, `FITAGENT_DATA_DIR`. Оценка цели, ответы и сводки используют одну модель.
Отправляются собственный User-Agent `fitagent/0.1.0` и стабильный `x-opencode-session`.

**Ограничение Go:** сервис ориентирован на coding-agent трафик. Применимость
подписки к фитнес-чату не подтверждена; интеграция оставлена по согласованию
с пользователем. Доступ, тарифы и лимиты определяет провайдер. Реальные платные
запросы при разработке не выполнялись. В настройках приватности Go для DeepSeek
может потребоваться разрешить регион Global.

## Интерфейс

Чат отвечает только о питании, тренировках, прогрессе и использовании FitAgent.
Для посторонних вопросов системный промпт предписывает краткий отказ с пояснением
тематики. В смешанных запросах агенту предписано отвечать только на часть по теме;
соблюдение этих правил зависит от модели, отдельного фильтра в приложении нет.

- `/profile` или Ctrl+P — профиль и изменение цели.
- `/progress` — последние 30 подтверждений веса и изменение за этот период.
- `/logs` или Ctrl+L — обновляемые технические события внутри приложения.
- `/clear` — **без подтверждения** удаляет профиль, все цели, переписку, изменения,
  сводки и логи; очищает экран, создаёт новую сессию и открывает заполнение профиля.
  `.env`, API-ключ и настройки подключения остаются без изменений.
- `/help` — краткая справка; Ctrl+Q — выход.
- `fitagent logs` — последние 200 событий без открытия TUI.

Во время ответа показывается монохромный анимированный индикатор с временем
ожидания. После ответа или ошибки он скрывается; фиктивного процента прогресса нет.

`/clear` выполняется, когда приложение не ожидает ответа модели. Все записи очищаются
одной транзакцией SQLite, файл БД остаётся пригодным для новой сессии. Это логическое
удаление, не гарантированное физическое стирание с носителя или из резервных копий.
Данные, уже переданные провайдеру модели, эта команда удалить не может.

При первом запуске заполните рост, вес, пол, возраст и цель. Целевой вес
необязателен. Числовые поля используют десятичную точку. Форма прокручивается;
кнопки доступны также через Tab. Для сохранения нужна успешная оценка цели API.

ИМТ целевого веса вне 18,5–24,9 вызывает предупреждение; модель дополнительно
оценивает формулировку, сроки и методы. Пока предупреждение не подтверждено,
цель не сохраняется. Можно исправить её вместо подтверждения. ИМТ не является
диагнозом и не учитывает мышечную массу; подтверждение не разрешает опасные советы.

Через 7 суток после подтверждения профиль запрашивается снова. Сохранение
без изменений тоже подтверждает актуальность. «Позже» оставляет старые измерения,
разрешает чат и переносит опрос на сутки, до следующего ответа. В запущенном
приложении срок проверяется каждую минуту; фоновых уведомлений нет.

## Данные, контекст и кеш

База: `~/.local/share/fitagent/fitagent.sqlite3`, либо `FITAGENT_DATA_DIR`.
Рассчитана на одного пользователя. Каждый профиль — новый снимок. Изменение
цели создаёт новую запись `goals`; последняя запись актуальна, старые остаются.
`messages` хранит отдельные вопросы/ответы с датой, временем и статусом,
`changes` — подтверждённые изменения по дням; `summaries` — кеш сводок,
`events` — технический аудит. При запуске экран восстанавливает всю сохранённую
переписку, включая сообщения старше недели; история доступна прокруткой без лимита
строк. Неудачные и незавершённые вопросы помечаются и автоматически не повторяются.
Отображение всей истории требует памяти пропорционально её объёму.
Ничего не удаляется при суммаризации.

Каждый запрос содержит постоянный системный промпт (консервативная оценка
меньше 3000 токенов) и полный актуальный профиль с целью. Ответы используют
историю за предыдущие 7 суток; неудачные/незавершённые запросы в контекст не входят.
При превышении бюджета истории 100 000 старая часть суммаризируется порциями,
последние полные записи в пределах бюджета 12 000 остаются дословными.
Сводка ограничена бюджетом 20 000. Для обычного ответа и проверки цели приложение
не передаёт max_tokens; лимиты генерации по умолчанию определяет API провайдера.
Ограничений длины вопроса и общего размера запроса в приложении нет;
предельный контекст определяет API провайдера.

**Учёт консервативный:** один UTF-8 байт считается верхней оценкой одного токена,
с отдельным резервом на формат сообщений. Это не точный токенизатор DeepSeek:
для русского текста суммаризация может начинаться заметно раньше 100 000
фактических токенов. Фактическая статистика API пишется в аудит, если доступна.
Результат сводки также проверяется по байтовому бюджету, без обрезания оригиналов.

Ключ кеша сводки включает модель, полный системный контекст и исходную историю.
Логи различают `summary_cache_hit`, начало/конец суммаризации, размеры контекста,
проверки профиля, подтверждение риска и ошибки API. `api_usage.cached_tokens` —
отдельный кеш провайдера; `null` означает, что API не сообщил статистику.
Логи объясняют решения приложения, а не раскрывают скрытые рассуждения модели.
Автоматических повторов платных запросов нет; при ошибке текст остаётся в поле ввода.

**Приватность:** SQLite не зашифрована (каталог создаётся с правами 700, файл — 600).
Профиль, цели и недельная история передаются внешнему API. Ключи, тексты
сообщений и значения профиля не записываются в технический аудит. Медицинские
рекомендации требуют проверки специалистом; приложение не заменяет врача.

## Проверки

```sh
.venv/bin/python3 -m pip install -r requirements-dev.txt
.venv/bin/python3 scripts/lint.py
.venv/bin/python3 -m unittest discover -s tests -v
```

Тесты используют подменный API: валидация, напоминания, история целей,
недельный контекст, суммаризация, кеш, ошибки и headless-сценарии Textual.
Документация каждого класса расположена рядом с исходным Python-файлом.
