# FactRepository

- Исходный файл: `fact_storage.py`
- Версия документа: 0.1.10
- Дата изменения: 2026-11-26

## Назначение
Транзакционное хранение фактов с постоянными номерами, их журналов и источников в SQLite.

## Основные обязанности
- Сохраняет условия незавершённого подбора атомарно с уточняющим вопросом.
- Создаёт таблицы памяти без изменения существующей переписки.
- Подготавливает изменения в памяти процесса; не сохраняет ответ модели до проверки.
- Фиксирует факты, источники, завершение вопроса и ответ одной транзакцией.
- В той же транзакции фиксирует этап/план цели с проверкой версии и активной цели;
  конкурентное изменение конвейера откатывает весь ответ и факты.
- При изменении обновляет существующую строку с тем же ID; прежние значения хранит в журнале.
- Не меняет дату создания; сохраняет источники всех обновлений и повторных подтверждений.
- Различает одинаковые ключи разных тем и хранит тему-источник каждого подтверждения.
- Мигрирует прежние факты/уточнения в global без потери значений, версий и цитат.
- Сохраняет lineage_id при изменении области применения; удаление очищает всю цепочку версий.
- Не переиспользует номера удалённых фактов; проверяет ревизию памяти и ID сессии перед записью.
- Читает факты, ID сессии и ревизию в одной явной транзакции SQLite.
- Не извлекает устаревший отложенный вопрос, если более новое сообщение уже обработано:
  последнее сообщение не может быть перезаписано поздно запущенной обработкой старого.
- Миграция добавляет superseded_at; до перехода возвращает также прежние версии.
- Для старых цепочек восстанавливает будущие границы из дат ревизий, без API и чтения текстов.
- Границы отложенных замен сохраняет в той же транзакции ответа; удаление очищает всю цепочку.
- Сохраняет подтверждения и завершение действующей прежней версии вместе с новым текущим фактом;
  отдельная цепочка нового факта не меняет запланированную версию другой области применения.
- При повреждённом JSON памяти не передаёт технический текст ошибки в TUI.
- Сохраняет старые многострочные цепочки для совместимости; их текущие номера не перенумеровывает.
- Отзыв и явное удаление сохраняют прежнюю политику; удаление очищает всю цепочку и журнал.
- Исправляет значение по команде пользователя без обращения к модели.
- Записывает журнал значений, дат действия, записи и источников в транзакции фактов.
- В той же транзакции пишет события изменения фактов: только действие и постоянный номер.
- События замены не появляются при ошибке ответа, подтверждения или откате записи.
- Локальное удаление записывает безопасное событие с номером факта, без текста и цитат.
- Показывает историю отдельного факта и архив среднесрочной памяти завершённых целей.
- /memory history НОМЕР показывает старые/новые значения, даты и русские названия действий.
- Журнал оформляется датами и строками «Было / Стало», подтверждение — строкой «Значение»;
  JSON и внутренние поля пользователю не показываются. Числа, единицы и оговорки сохраняются.
- Архив также показывает цель и понятные описания фактов, без сериализованных объектов.
- Повреждённые записи журнала/архива дают безопасную русскую ошибку без содержимого записи.
- Явное удаление факта очищает также его журнал; исходная переписка остаётся.

## Особенности
Извлекаются только новые вопросы через FitnessService; фонового разбора архива нет.
Идентичность факта — category/key/scope/applicability/topic_id; сопоставление предлагает модель.
В одном соединении проверяет статус исходного вопроса перед фиксацией.
