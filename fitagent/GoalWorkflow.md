# GoalWorkflow

- Исходный файл: `goal_workflow.py`
- Версия документа: 0.1.6
- Дата изменения: 2026-11-26

## Назначение
Строгий конвейер цели: планирование, валидация, выполнение, готово.

## Основные обязанности
- Использует последнее сохранённое значение веса независимо от давности и спрашивает только при отсутствии значения.
- Собирает недостающие общие сведения и уточняет просроченные по правилам памяти.
- Сохраняет известные ограничения безопасности независимо от давности.
- Проверяет конкретный черновик и критерий завершения через структурированный вызов модели.
- Предупреждение требует явного принятия плана; опасность подтверждением не снимается.
- При опасности объясняет причину и предлагает безопасные или пользовательские корректировки.
- Привязывает согласие к проверенным данным; изменение плана/данных требует новой валидации.
- При предложении замены любых критичных фактов, а не только ограничений, останавливает
  выполнение до подтверждения и новой валидации; неподтверждённое измерение не завершает цель.
- Изменения самочувствия и восстановления, включая локальную правку, входят в отпечаток данных
  и отменяют прежнюю проверку; простое подтверждение актуальности не сбрасывает согласие.
- Принимает только предложение, показанное в этом экземпляре: план, критерий, риск и данные.
- Запоминает показанное предложение после успешной записи ответа; чужое изменение сначала
  показывает заново, не применяя прежнее согласие. Открытие другого окна само по себе не мешает.
- Достижение с новым измерением предлагает подтвердить без создания нового плана;
  сведения для завершения привязывает к текущим данным и ранее принятому плану.
- При перезапуске восстанавливает ожидание подтверждения достижения, без API.
- Готовит состояние для атомарной фиксации вместе с фактами и ответом.
- Сброс проверки использует единое правило из goal_state; кандидат состояния готовится
  один раз на сообщение, без повторного присваивания в каждой ветке.
- При каждом открытии на этапе выполнения спрашивает о прогрессе без обращения к API.
- Передаёт принятый план в контекст ответов; сам не объявляет достижение цели.
- Передаёт планировщику согласованные период и формат текущего подбора питания.

## Особенности
Единственный обратный переход — выполнение → валидация.
Состояние каждой цели хранится в SQLite отдельно от переключаемых тем диалога.
Строгая схема не гарантирует медицинскую или смысловую точность модели.
