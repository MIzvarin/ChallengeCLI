# Storage

- Исходный файл: `storage.py`
- Версия документа: 0.1.13
- Дата изменения: 2026-11-22

## Назначение
Локальное хранилище SQLite для одного пользователя.

## Основные обязанности
- Хранит снимки профиля, историю целей, сообщения, изменения по дням и сводки.
- Сохраняет структурированные события без текстов переписки и ключей.
- logs сохраняет доступ к сырому внутреннему аудиту; activity_logs выдаёт активность,
  предупреждения/блокировки безопасности и ошибки проверки безопасности/памяти по-русски.
- Успешные проверки скрыты; этапы и статусы берутся из разрешённого словаря, без личных данных.
- Лимит 200 применяется после отбора значимых событий, шумные записи не вытесняют их.
- Некорректные записи активности пропускаются без вывода необработанных данных.
- Каждая операция использует собственное соединение, совместимое с рабочими потоками.
- Соединение всегда закрывается; ошибки откатывают транзакцию.
- Профиль и новая цель записываются одной транзакцией; последняя запись актуальна.
- Новая цель получает планирование; сохранение профиля сбрасывает прежнюю проверку плана,
  при выполнении возвращая только на валидацию. Состояния целей входят в очистку chat_state.
- Дата рождения обязательна для новых профилей; возраст вычисляется на текущую дату сервисом.
- Вес хранится измерениями sticky_facts; latest профиля выбирает последнее сообщение/обновление
  измерения, даже если его дата раньше других; при равных временах учитывается номер источника.
- weights читает последние 30 действующих измерений, включая сообщённые в чате.
- Сортирует измерения по датам с часовыми поясами и микросекундами; копию веса в профиле
  не восстанавливает после отзыва последнего измерения. Повреждённые данные не используются.
- Создаёт состояние опроса, подтверждения, журналы фактов и архив среднесрочной памяти.
- Для старого факта без журнала добавляет один явно помеченный снимок текущих сохранённых
  данных, без выдумывания прошлых изменений и смены ID. Повторное открытие его не дублирует.
- clear очищает также эти таблицы; завершённые цели не возвращаются как текущие.
- clear очищает основные таблицы, sticky_facts, fact_sources, memory_issues и memory_turns;
  создаёт новый ID сессии в одной транзакции.
- При открытии добавляет таблицы памяти, не извлекая факты из старой переписки.
- Создаёт topics, topic_messages, topic_transitions, checkpoints; старую завершённую
  переписку локально относит к одной общей теме, без API и семантической переклассификации.
- clear удаляет также все ветки, привязки, переходы и checkpoint-сводки.
- chat_messages возвращает всю переписку по порядку записи, включая статусы запросов.
- Для вопросов возвращает сохранённые отметки переходов, чтобы TUI восстановил их без API.
- history отдельно отбирает завершённые записи с заданной даты для контекста LLM.
- profile_history возвращает общие подтверждённые изменения профиля за период независимо от ветки.
- token_usage агрегирует api_request/api_usage всей переписки, без лимита 200 событий.
- При include_history=True возвращает также накопленную известную сумму для каждого обращения.
- Отчёт и точки графика вычисляются за один проход по одной выборке аудита, без миграции БД.
- Счётчики восстанавливаются из существующего аудита после перезапуска и сбрасываются /clear.
- Пропущенная статистика не заменяется нулём; кеш не прибавляется повторно ко входу.

## Особенности
База не зашифрована. Каталог создаётся с правами 700, файл с правами 600.
История не удаляется при суммаризации. Отложенный опрос не меняет дату измерений.
Очистка логическая: не является гарантией физического стирания с диска или из резервных копий.
Файлы вне SQLite, в том числе .env, не затрагиваются.
