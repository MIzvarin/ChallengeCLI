# FitnessService

- Исходный файл: `service.py`
- Версия документа: 0.1.28
- Дата изменения: 2026-11-26

## Назначение
Сценарии приложения независимо от терминального интерфейса.

## Основные обязанности
- Для явно связанных вопросов добавляет ограниченный фрагмент актуального плана дня
  в контекст чата, подбора питания и проверки безопасности как прежний ответ FitAgent.
- Для результата подбора меню выполняет проверки и регистрирует их статусы. В чат передаёт итог подбора или окончательную причину отказа без приложения промежуточных предупреждений.
- Передаёт моделям последний действующий вес без дат в объекте профиля. Даты остаются
  доступны в истории измерений.
- Явная команда и продолжение уточнения передают условия текущего подбора.
- При пустом журнале измерений использует сохранённый вес из снимка профиля.
- Распознаёт запрос меню в контексте темы и вызывает локальный MCP с актуальными фактами.
  Формирует общий контекст маршрутизации для чата и /plan. Оба пути используют извлечение
  памяти, выбор темы, сжатие истории и проверку изменений цели.
  В журнале отмечает идентификаторы использованных фактов и контрольных точек.
  Сохраняет ответ, тему и изменения памяти одной транзакцией.
- Первичный пошаговый чат-опрос, read-only профиль, изменения и подтверждения через чат.
- Пользовательский chat ведёт цель через GoalWorkflow; answer без manage_goal — низкоуровневый
  ответ для внутренних сценариев и изолированного тестирования чата.
- Подготовка предложений получает факты, вопрос и контекст без неиспользуемого результата проверки.
- При открытии продолжает конвейер; на выполнении каждый раз спрашивает о прогрессе без API.
- «Подтверждаю план» обрабатывает локально, без извлечения моделью случайных новых фактов.
- Ответ с планом фиксирует через GoalWorkflow.complete, связывая согласие с действительно
  выданным предложением в этом экземпляре; открытие конвейера само сохраняет своё сообщение.
- Перед генерацией выполнения включает принятый план и критерий в контекст и проверку безопасности.
- Вычисляет возраст из даты рождения на текущую дату; вес кандидата выбирает по последнему
  сообщению/подтверждению, а не по дате измерения, согласованно с профилем и памятью.
- Повторно проверяет параметры и предупреждение ИМТ перед сохранением.
- Ответы, оценка цели и сводки содержат постоянный промпт и несжатый профиль с целью.
- Один запрос к модели извлекает факты и выбирает ветку, имея каталог, checkpoint текущей темы
  и не более одного предыдущего обмена для понимания коротких согласий.
- Перед сборкой истории проверяет маршрут; ответ получает сообщения только активной темы.
- Её непокрытая checkpoint история за 7 суток передаётся дословно до 50 000 UTF-8 байт.
- Большая история суммаризируется порциями с бюджетом результата 20 000.
- Кеш сводки учитывает назначение, модель, системный контекст и исходную историю.
- Пишет причины технических решений без чувствительных текстов.
- Отмечает включённые в контекст ответа checkpoint и номера применимых фактов, без значений.
- После компакта (в том числе из кеша) отмечает фактический размер истории до/после в UTF-8 байтах.
- Оценивает общий размер запроса только для аудита, не ограничивает его отправку.
- Не ограничивает длину вопроса и генерацию ответа или оценки цели.
- Перед ответом извлекает факты из текущего вопроса через `FactMemory`.
- Передаёт закреплённые факты отдельным блоком, сохраняя недельную историю и суммаризацию.
- Flash создаёт checkpoint при уходе с темы; в смешанном вопросе — сводки связанных тем.
- Ответ, факты, ветки, переход, checkpoint и привязки обеих реплик фиксируются одной транзакцией.
- При ошибке извлечения/ответа/сохранения факты не изменяются, вопрос помечается failed.
- Сводки и checkpoint ограничены 20 000 токенов, структурированные запросы —
  8192 токенами, кроме сопоставления блюд с товарами ВкусВилла.
- Отдельные вызовы модели проверяют запрос, изменения ограничений/профиля и черновик ответа.
- Передаёт валидатору актуальную цель и тот же контекст темы/истории/checkpoints, что основной модели.
- Текст оценки цели проверяется отдельно до показа, включая повторно используемые предупреждения.
- Основная модель получает только статус и описание проверки; checks не передаются.
- block/ошибка протокола не сохраняют черновик и факты; warning показывается пользователю.
- После фиксации сообщает об изменениях памяти и сохраняет предложения подтверждения в чате.
- Завершение задачи/цели выполняет только по /confirm НОМЕР, с защитой ревизией и сессией.
- clear очищает хранилище и переключает клиент API на новый ID сессии.
- При подключённом NutritionShopping уточняет период/формат подбора до генерации рациона.
- Показывает готовую корзину с товарами вместо рекомендаций для самостоятельного меню.
- Дополняет проверенный черновик цели корзиной и оставляет план доступным для согласования.
- Перед показом цен или созданием ссылки проверяет ответ и составы товаров через SafetyGuard.
- При сбое поиска оставляет только рацион, при сбое создания ссылки сохраняет цены;
  ошибки безопасности не подавляются.
- Параметр nutrition необязателен для изолированных сценариев и тестов без сети.
- Самостоятельное меню не запускает и не меняет конвейер цели; принятый план остаётся
  ограничением в контексте. Изменение плана цели по-прежнему проходит GoalWorkflow.
- После нового предложения передаёт подбору актуальное, а не прежнее состояние плана.
- Общий блок подключает контекст цели для обычного чата и самостоятельного меню;
  инструкции ответа дополняются последовательно, без дублирующихся веток сборки.

## Особенности
Бюджеты считаются консервативно по UTF-8 байтам, не точным токенизатором DeepSeek.
Это может запускать суммаризацию раньше 50 000 фактических токенов.
Сводка не заменяет исходные данные SQLite. Ошибочные ответы не попадают в контекст.
Все временные метки должны иметь часовой пояс; часы подменяемы в тестах.
Предельный общий контекст определяет API провайдера, а не приложение.
