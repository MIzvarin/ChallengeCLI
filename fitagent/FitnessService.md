# FitnessService

- Исходный файл: `service.py`
- Версия документа: 0.1.4
- Дата изменения: 2026-11-10

## Назначение
Сценарии приложения независимо от терминального интерфейса.

## Основные обязанности
- Опрос раз в неделю, отсрочка на сутки, проверка и подтверждение цели.
- Повторно проверяет параметры и предупреждение ИМТ перед сохранением.
- Каждый запрос содержит постоянный системный промпт и несжатый профиль с целью.
- История за 7 суток передаётся дословно до бюджета 100 000.
- Большая история суммаризируется порциями с бюджетом результата 20 000.
- Кеш сводки учитывает модель, системный контекст и исходную историю.
- Пишет причины технических решений без чувствительных текстов.
- Оценивает общий размер запроса только для аудита, не ограничивает его отправку.
- Не ограничивает длину вопроса и генерацию ответа или оценки цели.
- Явный бюджет генерации остаётся только для суммаризации: 20 000.
- clear очищает хранилище и переключает клиент API на новый ID сессии.

## Особенности
Бюджеты считаются консервативно по UTF-8 байтам, не точным токенизатором DeepSeek.
Это может запускать суммаризацию раньше 100 000 фактических токенов.
Сводка не заменяет исходные данные SQLite. Ошибочные ответы не попадают в контекст.
Все временные метки должны иметь часовой пояс; часы подменяемы в тестах.
Предельный общий контекст определяет API провайдера, а не приложение.
