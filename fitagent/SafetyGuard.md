# SafetyGuard

- Исходный файл: `safety.py`
- Версия документа: 0.1.10
- Дата изменения: 2026-11-26

## Назначение
Отдельные вызовы модели проверяют безопасность до генерации и до показа ответа.

## Основные обязанности
- Получает вес из профиля как актуальный параметр без проверки срока давности.
- Передаёт ограничения, лекарства, добавки и профиль независимому валидатору.
- При подтверждении исправления передаёт также прежние правила, не теряя покрытие проверки.
- При одном постоянном ID у старого/нового значения использует отдельные номера проверок:
  fact:ID для нового и previous:ID для прежнего; отсутствие любой проверки блокирует запись.
- Новые запреты учитываются вместе со старыми ещё до подтверждения изменения записи.
- Предлагаемые изменения лекарств и добавок также входят в обязательное покрытие правил,
  даже если замена ещё ожидает подтверждения и в памяти остаётся прежняя схема приёма.
- Передаёт программу и режим как дополнительные данные, чтобы учитывать риски вне категорий.
- Получает актуальную/предлагаемую цель и контекст диалога для разрешения коротких ссылок.
- Проверяет все обязательные rule_id без искусственного лимита 64; лимит вывода API сохраняется.
- Передаёт исчерпывающий список required_rule_ids; количество checks ограничено этим списком.
- Отклоняет лишние/недостающие проверки и слишком длинные пояснения, не обрезая их вручную.
- Проверяет закрытую схему, покрытие правил и согласованность итогового статуса.
- Схема сначала запрашивает все проверки, затем итоговый статус и пояснение; несовпадение
  итогового статуса с самым строгим результатом по-прежнему считается ошибкой.
- Строгость назначает модель по данным; неизвестные подробности дают предупреждение.
- block предназначен для прямой угрозы жизни/тяжёлого вреда, не небольшого отклонения ИМТ.
- Для непроверенной желаемой цели и черновика может вернуть block как результат без разрешения
  выполнения: только этапы onboarding, goal_proposal и goal_plan поддерживают report_only.
- Валидация плана просит объяснение риска и безопасную корректировку; block нельзя подтвердить.
- Возвращает основной модели только статус и краткое описание, без массива checks.
- Блокирует конкретный запрос при block, сбое API или некорректном протоколе.
- При отказе объясняет, что нельзя выполнить на данном этапе, и приводит краткую причину из проверки.
- Предлагает безопасный вариант/другой вопрос; ошибочные ограничения исправляются с подтверждением.
- Сообщение о сбое проверки отличается от отказа из-за риска и не объявляет вопрос опасным.
- Для сбоя пишет этап, фазу получения/валидации, тип ошибки и фиксированный код причины.
- Ошибки протокола уточняют путь поля схемы, счётчики покрытия/длины и допустимые статусы.
- Не пишет содержимое ответа, описания рисков, номера правил или персональные данные.

## Особенности
Модель не гарантирует смысловую точность; строгий протокол не является медицинской гарантией.
